# 指标口径定义文档

## 1. 第一层：流量规模

| 指标 | 口径定义 | 计算逻辑（SQL） | 备注 |
|---|---|---|---|
| PV | 行为类型为 `pv` 的记录数 | `SUM(behavior_type = 'pv')` | 不去重，同一用户多次浏览重复计数 |
| UV | 有任意行为记录的独立用户数 | `COUNT(DISTINCT user_id)` | 全行为类型，非仅浏览 |
| 人均 PV | 平均每个用户产生的浏览量 | `SUM(behavior_type='pv') / COUNT(DISTINCT user_id)` | 用于衡量浏览深度 |
| 日 UV | 当日有任意行为记录的独立用户数 | `GROUP BY DATE(event_time)` 后 `COUNT(DISTINCT user_id)` | 日 UV 相加 ≠ 周期 UV，去重口径不同 |

脚本位置：`sql/01_overview.sql` 1.1、1.3

## 2. 第二层：转化效率（核心诊断层）

> **口径选择**：本层采用**用户级漏斗**——统计"用户是否发生过该行为"，而非"严格按时间顺序的会话级转化"。
> 原因：原始数据无 session 标识，无法可靠切分会话；用户级口径更稳健、更易解释。
> **代价**：用户级口径会高估转化。实测差异见第 5 节。

| 指标 | 口径定义 | 计算逻辑（SQL） | 备注 |
|---|---|---|---|
| 浏览用户数 | 发生过 `pv` 的独立用户数 | `COUNT(DISTINCT CASE WHEN behavior_type='pv' THEN user_id END)` | 漏斗第一层 |
| 加购用户数 | 发生过 `cart` 的独立用户数 | 同上，`behavior_type='cart'` | |
| 收藏用户数 | 发生过 `fav` 的独立用户数 | 同上，`behavior_type='fav'` | |
| 意向用户数 | 发生过 `cart` **或** `fav` 的独立用户数 | `COUNT(DISTINCT CASE WHEN behavior_type IN ('cart','fav') THEN user_id END)` | 漏斗第二层，加购与收藏合并 |
| 购买用户数 | 发生过 `buy` 的独立用户数 | 同上，`behavior_type='buy'` | 漏斗第三层 |
| 浏览→加购/收藏转化率 | 意向用户数 ÷ 浏览用户数 | `intent_uv / browse_uv` | 用户级 |
| 加购/收藏→购买转化率 | 购买用户数 ÷ 意向用户数 | `buy_uv / intent_uv` | 用户级，**核心瓶颈指标** |
| 整体转化率 | 购买用户数 ÷ 浏览用户数 | `buy_uv / browse_uv` | 北极星指标 |
| 加购→购买转化率 | 加购且购买的用户数 ÷ 加购用户数 | `SUM(has_cart AND has_buy) / SUM(has_cart)` | 用户级，与收藏路径并列对比 |
| 各环节流失率 | 1 − 该环节转化率 | `1 - 下一层人数 / 本层人数` | 用于定位瓶颈 |
| **严格有序转化率** | 首次浏览 < 首次加购 < 首次购买 的用户数 ÷ 浏览用户数 | 见 `sql/05_path_analysis.sql` 5.3 | **保守口径**，与用户级口径对照使用 |

实现位置：`sql/02_funnel.sql`、`sql/05_path_analysis.sql` 5.3

## 3. 第三层：用户留存

| 指标 | 口径定义 | 计算逻辑（SQL） | 备注 |
|---|---|---|---|
| cohort 起始日 | 用户在本数据期内**首次出现行为**的日期 | `MIN(DATE(event_time)) GROUP BY user_id` | 注意"新增"= 数据期内首次出现，非真实注册 |
| day_n | 距 cohort 起始日的天数（0 = 首访当天） | `DATEDIFF(DATE(event_time), cohort_date)` | |
| 次日留存率(D1) | cohort 中在第 1 天仍有行为的用户占比 | `COUNT(DISTINCT CASE WHEN day_n=1 ...) / cohort 人数` | 主口径（数据仅 9 天） |
| 3 日留存率(D3) | 同上，day_n = 3 | 同上 | |
| 7 日留存率(D7) | 同上，day_n = 7 | 同上 | 仅 cohort_date ≤ 11-26 的用户可观察 |
| 留存率矩阵 | cohort × day_n 的人数与留存率 | 见 `sql/03_retention.sql` 3.1 | 用于画热力图 |

**口径关键说明**：

1. 本定义是**精确日留存**（第 day_n 天当天有行为），不是**累计留存**（第 day_n 天及以后有行为），因此留存曲线不一定单调递减。
2. D1 / D3 / D7 的可观察 cohort 范围不同（9 天窗口限制），**三者的基期人群不一致，横向比较需谨慎**，报告中必须标注样本量。

实现位置：`sql/03_retention.sql`

## 4. 第四层：用户价值

| 指标 | 口径定义 | 计算逻辑（SQL） | 备注 |
|---|---|---|---|
| R（Recency） | 用户最后一次行为日期距数据截止日的天数，越小越活跃 | `DATEDIFF(数据截止日, MAX(DATE(event_time)))` | 以数据截止日 2017-12-03 为基准 |
| F（Frequency） | 用户在数据期内 `buy` 行为次数 | `SUM(behavior_type='buy')` | 即购买次数，不是行为总次数 |
| M（Monetary） | **不计算** | — | 原始数据无金额字段，故本项目为 **RF 分层**，不称 RFM |
| R 高低分层 | R ≤ 全体均值 → R高，否则 R低 | `CASE WHEN recency <= AVG(recency) OVER () ...` | 阈值用均值，报告中需说明 |
| F 高低分层 | F ≥ 全体均值 → F高，否则 F低 | 同上 | |
| 分层命名 | 重要价值(R高F高) / 重要发展(R高F低) / 重要保持(R低F高) / 一般客户(R低F低) | 见 `sql/04_rf_segmentation.sql` 4.1 | 四象限 |
| 活跃天数 | 用户有行为记录的自然日数量 | `COUNT(DISTINCT DATE(event_time))` | R 区分度不足时的替代活跃度指标 |
| 用户频次分层 | 高频 ≥100 次 / 中频 30-99 次 / 低频 <30 次 | `COUNT(*)` 分层 | 阈值基于样本分布确定，全量需重算 |

实现位置：`sql/04_rf_segmentation.sql`、`sql/06_drilldown_attribution.sql` 6.3

## 5. 口径差异实测：用户级 vs 严格有序

| 口径 | 整体转化率 | 说明 |
|---|---|---|
| 用户级漏斗 | **69.25%** | 只要求"发生过"，不要求顺序 |
| 严格有序漏斗 | **29.25%** | 要求 首次浏览 < 首次加购 < 首次购买 |

## 6. 已知限制对指标的影响

| 限制 | 影响的指标 | 处理方式 |
|---|---|---|
| 无金额字段 | 无法计算 GMV、客单价、M | 明确做 RF 分层，不虚构金额指标 |
| 无 session 标识 | 漏斗无法做会话级 | 主口径用用户级，并给出严格有序口径作为对照 |
| 行为非严格时序 | 漏斗可能高估 | 已在第 5 节量化高估幅度 |
| 仅 9 天数据 | 留存最多算到 D7 | 主口径用次日留存，D3/D7 标注 cohort 范围 |
| 数据截止日为流量峰值日 | R 维度失效（998 人中仅 23 人 recency ≥ 1） | RF 分层结果仅作参考，建议改用 F 分层或活跃天数 |
| 已脱敏 ID | 无法关联用户画像 | 归因维度限定为类目、时段、行为频次 |
